# Product Management Specification: Personal News & Media Aggregator Evolution

## 1. Executive Summary
The goal is to evolve the current RSS-based daily digest into a comprehensive personal media intelligence hub. This includes removing technical debt, fixing UX glitches, and expanding the system to include YouTube and YouTube-based Podcasts, all while maintaining a "built for one person" philosophy.

## 2. Problem Statements & Resolution

### 2.1 Technical Debt & UX Fixes
| Issue | Requirement | Resolution |
| :--- | :--- | :--- |
| **Hardcoded Prompts** | Prompts are hidden in `service.py`, making updates tedious. | Move prompts to `.md` files. Implement a `PromptManager` to load prompts based on "Detail Level" (High-level vs. Detailed) and Creator. |
| **Static RSS Config** | Adding feeds requires manual `.xml` edits. | Migrate `main.xml` to `aggregator.db`. Create a UI for adding/removing feeds with URL validation. |
| **Digest History Bug** | Switching from monthly view back to "All" causes a JSON error. | Fix frontend state management to properly reset filters without breaking the API request. |
| **UI Polish** | Unprofessional callouts and file references in "Sources". | Remove "RSS Digest — Personal news aggregator..." callout and the "RSS Feeds main.xml" reference. |
| **Dark Mode Flash** | Visual lag/flash when loading articles in dark mode. | Implement a blocking theme-detection script in the `<head>` or use CSS variables on the `<html>` tag to ensure instant theme application. |

### 2.2 New Feature: YouTube & Podcast Intelligence
The system will extend its scraping and summarization capabilities to YouTube videos and YouTube-based podcasts.

#### A. Core Functionality
- **Automated Extraction:** Daily scraping of transcripts for followed creators.
- **Cost-Efficient Transcription:** Use free, open-source APIs for transcript extraction (leveraging existing YouTube captions where available) to avoid GPU costs.
- **Summarization:** Apply the same LLM summarization pipeline used for RSS, but with the ability to toggle detail levels per creator.
- **Grouping:** 
    - **Daily View:** A chronological list of all new media across all creators.
    - **Creator View:** A dedicated toggle/view to see the history and summaries of a specific creator.

#### B. YouTube Integration & OAuth
- **One-Time Sync:** Implement a simple OAuth flow for a single user (the owner).
- **Subscription Sync:** Use the OAuth token to automatically import the list of followed channels and podcasts from the YouTube account, eliminating manual entry.

## 3. Functional Requirements

### 3.1 Backend (The Engine)
- **Database Migration:** 
    - Move RSS source list from `main.xml` to a `sources` table in `aggregator.db`.
    - Create tables for `youtube_channels` and `transcripts`.
- **Prompt Engine:** 
    - Create a directory `@Main Architecture/prompts/`.
    - Logic: `get_prompt(creator_id, detail_level)`.
- **Sync Worker:** 
    - Update the existing Cron job to include:
        1. RSS Fetch $\rightarrow$ Summarize.
        2. YouTube Transcript Fetch $\rightarrow$ Summarize.
        3. Podcast (YouTube) Transcript Fetch $\rightarrow$ Summarize.

### 3.2 Frontend (The Interface)
- **Navigation:** 
    - Primary navigation to switch between: `RSS Digest` | `YouTube Insights` | `Podcast Insights`.
- **Source Management Page:** 
    - A unified "Settings" page to:
        - Manage RSS links (Add/Delete/Validate).
        - Manage YouTube Channels (Add/Delete/Sync via OAuth).
        - Manual "Sync Now" trigger.
- **Content Consumption:** 
    - Unified "Digest Card" design for all media types.
    - Link to original source (Article/Video).
    - Toggle for "Detail Level" (if applicable).

## 4. Success Criteria
- [ ] Adding an RSS feed via UI instantly updates the database and is reflected in the next run.
- [ ] YouTube subscriptions are imported via OAuth without manual input.
- [ ] No visual "flash" when loading articles in dark mode.
- [ ] "All months" view in history loads without JSON errors.
- [ ] Prompts can be changed in `.md` files without touching Python code.
- [ ] Summaries for YouTube/Podcasts are generated using free/open-source transcript methods.
