## 2. Change 1 — Prompt Engine

### 2.1 Problem
All LLM prompts are hardcoded as module-level constants in `app/summarizer/service.py`:
- `_SINGLE_SUMMARY_PROMPT`
- `_CHUNK_SUMMARY_PROMPT`
- `_REDUCE_PROMPT`
- `_DIGEST_PROMPT`

Changing them requires editing Python code and redeploying.

### 2.2 Solution

Create a `Main Architechture/prompts/` directory (single source of truth) with one `.md` file per prompt template. Implement a `PromptManager` class that loads prompts by detail level and creator/channel.

#### Directory Structure

```
Main Architechture/
├── prompts/
│   ├── single_summary.md        # _SINGLE_SUMMARY_PROMPT equivalent
│   ├── chunk_summary.md         # _CHUNK_SUMMARY_PROMPT equivalent
│   ├── reduce_synthesis.md      # _REDUCE_PROMPT equivalent
│   ├── daily_digest.md          # _DIGEST_PROMPT equivalent
│   ├── youtube_summary.md       # YouTube-specific prompt (optional overrides)
│   └── podcast_summary.md       # Podcast-specific prompt (optional overrides)
└── (existing files...)
```

Each `.md` file uses a `{placeholder}` syntax matching Python's `str.format()`.

#### Implementation: `app/prompts/manager.py`

```python
"""PromptManager — loads prompt templates from .md files.

Prompts are stored as Markdown files in Main Architechture/prompts/
and cached in memory after first load.

Detail level filter: "high-level" vs "detailed" (future use).
Creator filter: allows per-creator prompt overrides (future use for YouTube/podcasts).
"""

import os
import logging
from pathlib import Path
from functools import lru_cache

logger = logging.getLogger(__name__)

PROMPTS_DIR = Path(__file__).resolve().parent.parent.parent / "Main Architechture" / "prompts"
FALLBACK_PROMPTS = {
    "single_summary": "Summarize the following article concisely:\n\n{text}",
    "chunk_summary": "Summarize this excerpt:\n\n{text}",
    "reduce_synthesis": "Synthesize these sub-summaries:\n\n{sub_summaries}",
    "daily_digest": "Create a daily digest:\n\n{article_summaries}",
}

class PromptManager:
    """Manages prompt templates loaded from .md files with caching."""

    def __init__(self, prompts_dir: str | Path | None = None):
        self.prompts_dir = Path(prompts_dir) if prompts_dir else PROMPTS_DIR

    def get_prompt(
        self,
        template_name: str,
        detail_level: str = "detailed",
        creator: str | None = None,
    ) -> str:
        """Get a prompt template by name.

        Resolution order (first match wins):
        1. {prompts_dir}/{creator}/{detail_level}/{template_name}.md
        2. {prompts_dir}/{creator}/{template_name}.md
        3. {prompts_dir}/{detail_level}/{template_name}.md
        4. {prompts_dir}/{template_name}.md
        5. Built-in fallback
        """
        candidates = []

        if creator:
            candidates.append(self.prompts_dir / creator / detail_level / f"{template_name}.md")
            candidates.append(self.prompts_dir / creator / f"{template_name}.md")

        candidates.append(self.prompts_dir / detail_level / f"{template_name}.md")
        candidates.append(self.prompts_dir / f"{template_name}.md")

        for path in candidates:
            if path.exists():
                logger.debug(f"Loading prompt from {path}")
                return path.read_text(encoding="utf-8").strip()

        logger.warning(f"Prompt '{template_name}' not found, using fallback")
        return FALLBACK_PROMPTS.get(template_name, "")

    def list_available_prompts(self) -> list[str]:
        """List all available .md prompt templates."""
        if not self.prompts_dir.exists():
            return []
        return sorted(
            p.stem for p in self.prompts_dir.glob("**/*.md")
        )

# Singleton
prompt_manager = PromptManager()
```

## 3. Change 2 — RSS Source Management UI + DB Migration

### 3.1 Problem
RSS sources are currently loaded from `RSS Feeds main.xml` at scrape time (`app/scraper/service.py` calls `parse_opml()`). Adding a new feed means editing the XML file manually.

### 3.2 Solution
Import all existing feeds from OPML into the `sources` table (done at startup or via migration), then replace OPML-based loading with DB-based loading. Add a Settings page UI for managing feeds.

#### Database Migration

The `sources` table already exists. The only change needed is a one-time import script and a flag to switch from OPML to DB.

```python
# scripts/import_opml_to_db.py
"""One-time script: import RSS Feeds main.xml into the sources table."""

from app.database import get_db, upsert_source
from app.scraper.feed_reader import parse_opml

def import_opml(opml_path: str = "RSS Feeds main.xml") -> int:
    """Import all feeds from OPML into the sources table.
    Returns the number of feeds imported.
    """
    conn = get_db()
    try:
        feeds = parse_opml(opml_path)
        count = 0
        for feed in feeds:
            upsert_source(
                conn,
                name=feed["name"],
                feed_url=feed["xmlUrl"],
                site_url=feed.get("htmlUrl", ""),
                category=feed.get("category", ""),
            )
            count += 1
        conn.commit()
        return count
    finally:
        conn.close()

if __name__ == "__main__":
    count = import_opml()
    print(f"Imported {count} feeds into database.")
```

## 4. Change 3 — Digest History Bug Fix

### 4.1 Problem
Switching from monthly view back to "All months" in the history page causes a JSON error. Root cause: when `month` is empty (no value), the query string becomes `/history?year=2026&month=` which sends an empty string as the month parameter, causing the SQL query to fail.

### 4.2 Solution

#### Fix 1: Client-side fix in `history.html`

Change the `<select>` `onchange` to omit the `month` parameter entirely when "All months" is selected:

```html
<select onchange="
    const val = this.value;
    const base = '/history?year={{ selected_year }}';
    window.location.href = val ? base + '&month=' + val : base;
">
    <option value="">All months</option>
    ...
</select>
```

#### Fix 2: Robust SQL query

In `app/database.py::get_all_digests()`, ensure month filtering is robust against empty/None:

```python
if month and month > 0:
    conditions.append("strftime('%m', date) = ?")
    params.append(f"{int(month):02d}")
```

#### Fix 3: Server-side coercion (defensive)

In `app/web/routes.py::history()`:
```python

if month == "" or month == 0:
    month = None
```

## 6. Change 5 — Dark Mode Flash Fix

### 6.1 Problem
The dark mode theme is applied via a script at the bottom of `<body>` after the page renders, causing a brief flash of light mode before dark mode kicks in.

### 6.2 Solution
Move the theme-detection logic into a blocking `<script>` in `<head>`, before any CSS renders:

#### In `app/web/templates/base.html`

```html
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>{% block title %}RSS Digest{% endblock %}</title>
    <link rel="icon" href="data:image/svg+xml,..." type="image/svg+xml">

    {# ── Blocking theme script — prevents flash ── #}
    <script>
    (function() {
        const saved = localStorage.getItem('theme');
        const prefersDark = window.matchMedia('(prefers-color-scheme: dark)').matches;
        if (saved === 'dark' || (!saved && prefersDark)) {
            document.documentElement.setAttribute('data-theme', 'dark');
            // Inject a style to prevent any flash
            document.documentElement.style.setProperty('--bg', '#0f172a');
            document.documentElement.style.setProperty('--bg-card', '#1e293b');
            document.documentElement.style.setProperty('--text', '#e2e8f0');
        }
    })();
    </script>

    <link rel="stylesheet" href="/static/style.css">
    {% block head_extra %}{% endblock %}
</head>
```

The existing `<script>` block at the bottom of `<body>` should be simplified to only handle toggle clicks (not initial theme application):

```html
<script>
// Dark mode toggle — only handles clicks, no flash-prone initialisation
(function() {
    const toggle = document.getElementById('themeToggle');
    const html = document.documentElement;

    // Set toggle icon based on current state (already applied by head script)
    const isDark = html.getAttribute('data-theme') === 'dark';
    toggle.textContent = isDark ? '🌙' : '☀️';

    toggle.addEventListener('click', () => {
        const isDark = html.getAttribute('data-theme') === 'dark';
        if (isDark) {
            html.removeAttribute('data-theme');
            toggle.textContent = '☀️';
            localStorage.setItem('theme', 'light');
        } else {
            html.setAttribute('data-theme', 'dark');
            toggle.textContent = '🌙';
            localStorage.setItem('theme', 'dark');
        }
    });
})();
</script>
```

#### CSS Transition Guard

In `style.css`, add a class to prevent transition flashes:
```css
html:not(.theme-ready) body { transition: none !important; }
```

And add `document.documentElement.classList.add('theme-ready')` after the blocking script in `<head>`.

#### `transcript_fetcher.py`

```python
"""Fetch YouTube video transcripts using youtube-transcript-api.
Free, open-source, uses YouTube's existing captions. No API key needed.
"""

import logging
from typing import Optional
from youtube_transcript_api import YouTubeTranscriptApi
from youtube_transcript_api.formatters import TextFormatter

logger = logging.getLogger(__name__)

def fetch_transcript(video_id: str, languages: list[str] | None = None) -> Optional[str]:
    """Fetch transcript for a YouTube video."""
    try:
        transcript_list = YouTubeTranscriptApi.list_transcripts(video_id)
        transcript = None
        try:
            transcript = transcript_list.find_manually_created_transcript(
                languages or ['en']
            )
        except Exception:
            try:
                transcript = transcript_list.find_generated_transcript(
                    languages or ['en']
                )
            except Exception:
                logger.warning(f"No transcript found for video {video_id}")
                return None

        if transcript:
            formatter = TextFormatter()
            return formatter.format_transcript(transcript.fetch())
    except Exception as e:
        logger.error(f"Failed to fetch transcript for {video_id}: {e}")
    return None
```

#### `channel_scanner.py`

Uses `yt-dlp` to list recent videos from a channel without requiring an API key.

```python
import yt_dlp
from datetime import datetime, timezone, timedelta
from app.config import settings

def get_recent_videos(channel_id: str, lookback_hours: int | None = None) -> list[dict]:
    lookback = lookback_hours or settings.lookback_hours
    cutoff = datetime.now(timezone.utc) - timedelta(hours=lookback)
    url = f"https://www.youtube.com/channel/{channel_id}/videos"

    ydl_opts = {"quiet": True, "no_warnings": True, "extract_flat": True}
    with yt_dlp.YoutubeDL(ydl_opts) as ydl:
        info = ydl.extract_info(url, download=False)
        entries = info.get("entries", [])
        videos = []
        for entry in entries:
            if not entry or not entry.get("id"):
                continue
            published_str = entry.get("upload_date")
            if published_str:
                published = datetime.strptime(published_str, "%Y%m%d").replace(tzinfo=timezone.utc)
                if published < cutoff:
                    continue
                videos.append({
                    "video_id": entry["id"],
                    "title": entry.get("title", "Untitled"),
                    "published_at": published,
                    "url": f"https://youtube.com/watch?v={entry['id']}",
                    "duration_secs": entry.get("duration"),
                })
        return videos
```

```python
def daily_scrape_and_summarize() -> None:
```
